# Отчёт: метрики City Guide в Grafana

## Источник данных

В качестве источника по умолчанию используется VictoriaMetrics с Prometheus-совместимым API. Grafana подключается к ней по адресу `http://vm-single-victoria-metrics-single-server.monitoring.svc:8428`. `vmagent` собирает метрики API, пробера и PostgreSQL exporter в namespace `cityguide` и отправляет их в VictoriaMetrics.

## Дашборд приложения

Дашборд создан и редактируется через интерфейс Grafana. Для верхнеуровневого состояния приложения используются RED-панели: частота запросов, доля ошибок и p95 задержки. Панели CPU, памяти и сборщика мусора дают детализацию рантайма и USE-утилизации процесса. SLA пробера вынесен отдельно от SLI пользовательских запросов API.

| Панель | PromQL | Назначение |
|---|---|---|
| RPS по маршрутам | `sum by (route) (rate(cityguide_api_requests_total[5m]))` | RED: скорость поступления пользовательских запросов. |
| Доля 5xx, % | `100 * sum(rate(cityguide_api_requests_total{outcome="bad"}[5m])) / clamp_min(sum(rate(cityguide_api_requests_total[5m])), 0.001)` | RED: доля запросов с серверной ошибкой. |
| p95 задержки, сек | `histogram_quantile(0.95, sum by (le) (rate(cityguide_api_request_duration_seconds_bucket[5m])))` | RED: хвостовая задержка API. |
| Probe SLA, % за выбранный интервал | `100 * avg_over_time(cityguide_probe_success[$__range])` | Доля успешных синтетических проверок API за выбранный период. |
| Последняя проверка | `cityguide_probe_success` | 1 — успешно, 0 — ошибка. |
| Длительность проверки, сек | `cityguide_probe_duration_seconds` | Время последнего запроса пробера. |
| Память API по Pod | `process_resident_memory_bytes{kubernetes_namespace="cityguide", kubernetes_pod_name=~"api-[a-z0-9]+-[a-z0-9]+"}` | USE: потребление памяти процессом API. |
| CPU API по Pod | `rate(process_cpu_seconds_total{kubernetes_namespace="cityguide", kubernetes_pod_name=~"api-[a-z0-9]+-[a-z0-9]+"}[5m])` | USE: использование CPU процессом API, в ядрах. |
| Циклы сборщика мусора | `rate(python_gc_collections_total{kubernetes_namespace="cityguide", kubernetes_pod_name=~"api-[a-z0-9]+-[a-z0-9]+"}[5m])` | Активность сборщика мусора Python по поколениям. |

`cityguide_api_requests_total` и `cityguide_api_request_duration_seconds` учитывают пользовательские маршруты `/api/`; `/health` и `/metrics` исключены, чтобы проверки и scrape не влияли на SLI.

## PostgreSQL Exporter

PostgreSQL exporter запускается рядом с базой и предоставляет статистику PostgreSQL в формате Prometheus на порту `9187`. Он не является базой данных и не хранит метрики: `vmagent` собирает их, VictoriaMetrics хранит, Grafana визуализирует.

Для демонстрации можно импортировать готовый дашборд [PostgreSQL Database, Grafana.com ID 9628](https://grafana.com/grafana/dashboards/9628-postgresql-database/). Он показывает типовые показатели соединений, транзакций и состояния базы. После импорта выберите datasource `VictoriaMetrics`; запрос `pg_up` должен возвращать `1`.

## Импорт и сохранение дашборда

1. Откройте Grafana по адресу `http://localhost:3000`. Имя пользователя и пароль задаются в `k8s/grafana-values.yaml`: `admin` / `admin`.
2. Выберите **Dashboards → New → Import dashboard** и загрузите [`grafana/city-guide-application-sla.json`](grafana/city-guide-application-sla.json). В JSON есть панели RPS, ошибок, p95, SLA пробера, CPU, памяти, Python GC и статуса `pg_up`.
3. Дашборд ссылается на datasource UID `victoriametrics`, настроенный в `k8s/grafana-values.yaml`. Если импортёр предложит выбрать источник, укажите `VictoriaMetrics`.
4. Для PostgreSQL откройте **Dashboards → New → Import dashboard**, введите ID `9628`, выберите `VictoriaMetrics` в datasource-поле и импортируйте.
5. После импорта панели можно редактировать в UI и сохранять кнопкой **Save dashboard**. Для резервной копии или переноса используйте **Share/Export → Export as JSON**.

В Helm values включён PVC для Grafana размером 2 GiB. Поэтому дашборды, созданные в UI, сохраняются в базе Grafana на PVC и переживают обычный перезапуск Pod’а или остановку/запуск того же Minikube-кластера. При удалении кластера (`minikube delete`) его PVC также удаляется. Для переноса или резервной копии экспортируйте каждый дашборд из меню **Share/Export** (Classic JSON) и сохраните JSON отдельно; его можно импортировать в новую Grafana через **Dashboards → New → Import**.

После сохранения дашборда приложите в отчёт скриншоты приложения и импортированного PostgreSQL-дашборда, а в скринкасте покажите оба.
